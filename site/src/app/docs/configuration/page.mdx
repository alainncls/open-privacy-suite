# Configuration Reference

All Open Privacy Suite configuration is driven by environment variables. This page documents every variable, their defaults, and how they interact across development and production modes.

---

## Required in Production

These variables **must** be set when `ENVIRONMENT=production`. The server will refuse to start without them.

| Variable | Description |
|----------|-------------|
| `JWT_SECRET` | Secret for signing access tokens |
| `JWT_REFRESH_SECRET` | Secret for signing refresh tokens |
| `VERIFIER_ID` | Your Privado verifier DID |
| `ADMIN_API_TOKEN` | Shared token for admin API authentication (M2M / bootstrap) |
| `DATABASE_URL` | PostgreSQL connection string |

## Runtime Tracing

<EnvTable vars={[
  { name: "ENABLE_RUNTIME_TRACING", default: "true (docker)", description: "Enable runtime transaction tracing for cross-org isolation" },
]} />

When enabled, the proxy uses `debug_traceCall` to validate all addresses touched by transactions before forwarding them to the node. This provides comprehensive cross-organization isolation:

- **All internal CALL/DELEGATECALL/STATICCALL targets are validated** against RBAC permissions
- **Custom Multicall contracts are detected** -- any contract batching calls will have all targets validated
- **CREATE/CREATE2 in runtime is blocked** -- prevents unauthorized contract deployment
- **Precompiles (0x01--0x09) are always allowed**

**Node requirements:**

- Upstream node must support `debug_traceCall` (Geth, Anvil, Erigon, Nethermind)
- For Geth: the `--http.api debug` flag is required

**Performance impact:**

- Adds approximately 50--200 ms latency per transaction
- Tiered validation skips tracing for calls to known org-owned addresses
- Caching reduces overhead for repeated patterns

## RPC API Keys and Upstream Rate Limiting

When the privacy proxy forwards requests to an upstream RPC node (or RPC proxy service), it can
attach a per-group API key as a `Bearer` token in the `Authorization` header.

<EnvTable vars={[
  { name: "RPC_API_KEY", default: "(none)", description: "Global fallback API key sent to the upstream RPC node. Used when no group-specific key is configured." },
  { name: "RPC_API_KEY_ENCRYPTION_KEY", default: "(none)", description: "Hex-encoded 32-byte key for AES-256-GCM encryption of per-group RPC API keys at rest. When set, keys are encrypted before writing to the database and decrypted on read. When empty (dev mode), keys are stored in plaintext." },
  { name: "MAX_CONCURRENT_REQUESTS", default: "50", description: "Maximum concurrent in-flight requests per user. Protects proxy resources from being exhausted by a single user." },
]} />

**Per-group keys** can be configured via the admin API (`rpc_api_key` field on group access settings)
or the admin dashboard. When a user belongs to a group with an `rpc_api_key`, that key is used
instead of the global fallback.

**Encryption at rest:** When `RPC_API_KEY_ENCRYPTION_KEY` is set, per-group API keys are encrypted
with AES-256-GCM before storage and decrypted transparently when resolved for forwarding. Generate
a key with `openssl rand -hex 32`. Legacy plaintext values are handled gracefully during the
transition period (decryption falls back to passthrough for non-encrypted values).

**Masked in API responses:** API keys are never returned in full from the admin API. Responses show
only the last 4 characters (e.g., `****c123`). The frontend should treat an empty `rpc_api_key`
field as "keep existing" when editing.

**IP forwarding:** The client's IP address is forwarded to the upstream RPC node via
the `X-Forwarded-For` header, enabling upstream rate limiting and audit logging per client.

**Circuit breaker:** If the upstream returns HTTP 429 (Too Many Requests), the proxy trips a
per-key circuit breaker with a 1-second cooldown. During cooldown, requests using that key are
rejected immediately with `"upstream rate limited, retry in 1s"` instead of forwarding to the
node.

**Concurrency limiter:** Each user is capped at `MAX_CONCURRENT_REQUESTS` in-flight requests.
Excess requests are rejected with HTTP 429 `"too many concurrent requests"`. This protects
the proxy's own resources (DB connections, memory) from being exhausted by a single user.

**Prometheus metrics:** The following metrics are exposed for monitoring:
- `privacyproxy_circuit_breaker_trips_total` (label: `api_key_masked`) -- circuit breaker rejections
- `privacyproxy_concurrency_rejections_total` -- per-user concurrency limit rejections
- `privacyproxy_upstream_rate_limit_total` (label: `api_key_masked`) -- HTTP 429 from upstream

<Callout variant="warning" title="API key label safety">
  Metric labels use masked API keys (last 4 characters only). Full keys are never exposed in metrics.
</Callout>

## Rate Limiting (Deprecated)

Rate limits are configured per-user via the RBAC system:

- **`rate_limit_rps`** -- Requests per second (sliding window)
- **`rate_limit_daily`** -- Daily request limit (resets at UTC midnight)

Exceeding either limit returns HTTP 429 Too Many Requests.

<Callout variant="info" title="Deprecated">
  Per-group rate limits (`rate_limit_rps`, `rate_limit_daily`) are deprecated. Upstream rate
  limiting is now handled by per-group RPC API keys with circuit breaker protection. The old
  rate limiter is still used for anonymous (unauthenticated) access.
</Callout>

## Environment Modes

### Development (`ENVIRONMENT=development`)

- `/auth/verify` endpoint enabled for manual testing
- JWT secrets auto-generated if not set
- `REQUIRE_PROOF_OF_HUMANITY` defaults to `false`
- Mock tokens accepted: `mock.{did}` or `mock.jwz.token.{did}`
- Mock-login users are auto-granted the `admin` claim (instant admin dashboard access)

### Production (`ENVIRONMENT=production`)

- `/auth/verify` endpoint disabled
- JWT secrets required (server will not start without them)
- `REQUIRE_PROOF_OF_HUMANITY` defaults to `true`
- `VERIFIER_ID` required
- `ADMIN_API_TOKEN` required (server will not start without it)

<Callout variant="warning" title="Development-only features">
  Mock tokens and the `/auth/verify` endpoint are disabled in production mode. Do not rely on them for integration testing against a production deployment.
</Callout>

The `docker-compose.e2e.yml` file replaces the mock node with Anvil for realistic testing:

```bash
make e2e          # Run full suite
make e2e-debug    # Keep services running after tests
make e2e-down     # Stop services
```

## Database

### Connection

Uses pgx v5 with the standard `database/sql` interface.

```bash
# Local development
DATABASE_URL=postgres://postgres:postgres@localhost:5432/privacy_proxy?sslmode=disable

# Docker
DATABASE_URL=postgres://postgres:postgres@postgres:5432/privacy_proxy?sslmode=disable
```

### Migrations

Uses Tern v2 with embedded migrations in `internal/db/migrations/`.

```bash
# Run migrations
make db-migrate

# Create new migration
make db-new-migration name=add_feature
```

<Callout variant="info" title="Migration policy">
  Migrations are expand-only in production. Never use DROP in UP migrations. If a migration needs undoing, create a new forward migration.
</Callout>

## Trusted Proxies

For Docker environments, the server trusts `X-Forwarded-For` from:

- `172.16.0.0/12` (Docker networks)
- `127.0.0.1` (localhost)

Adjust in `internal/server/server.go` if your deployment requires additional trusted ranges.

## Example .env

```bash
# Required for production
ENVIRONMENT=production
JWT_SECRET=your-secure-secret-here
JWT_REFRESH_SECRET=your-refresh-secret-here
VERIFIER_ID=did:polygonid:polygon:main:your-verifier-did

# Database
DATABASE_URL=postgres://user:pass@host:5432/dbname?sslmode=require

# Ethereum node
NODE_URL=https://eth-mainnet.alchemyapi.io/v2/your-key

# Privado
PRIVADO_RPC_URL=https://rpc-mainnet.privado.id

# ProofOfHumanity (optional)
BILLIONS_ISSUER_DID=did:polygonid:polygon:main:billions-issuer-did
REQUIRE_PROOF_OF_HUMANITY=true

# Runtime Tracing (recommended for production)
ENABLE_RUNTIME_TRACING=true

# Admin API
ADMIN_API_TOKEN=your-admin-token-here

# RPC API key encryption (generate with: openssl rand -hex 32)
RPC_API_KEY_ENCRYPTION_KEY=your-64-char-hex-string-here

# Public URL
BASE_URL=https://your-domain.com
```
